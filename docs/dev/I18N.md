# i18n (Internationalisierung)

Konventions- und How-to-Doku für die zentrale String-Schicht in `src/i18n.rs`.
Die übergeordneten Entscheidungen stehen in `AGENTS.md` → „Internationalisierung (i18n)";
dieses Dokument beschreibt den **aktuellen Code** (Stand 2026-11-10, Rune ist der einzige
UI-Host; die eframe-API ist entfallen).

## 1. Konzept

Deutsch ist die **Quelle und zugleich der Key**: der deutsche UI-Satz, den der Nutzer im
Referenzzustand sieht, ist buchstäblich der Schlüssel im Code.

- `Lang::De` → `tr(key)` gibt den Key **unverändert** zurück (Referenzsprache).
- `Lang::En` → `tr(key)` sucht den Eintrag in der Tabelle `EN` und gibt ihn zurück.
- **Unbekannter Key** (kein Tabelleneintrag) → Fallback auf den deutschen Key. Eine Lücke
  degradiert also zu Deutsch statt zu brechen.

```rust
// src/i18n.rs
pub(crate) fn tr(key: &'static str) -> &'static str {
    match lang() {
        Lang::De => key,
        Lang::En => EN
            .iter()
            .find(|(de, _)| *de == key)
            .map(|(_, en)| *en)
            .unwrap_or(key),
    }
}
```

Die aktuelle Sprache ist ein **prozess-globaler** Wert (`static CURRENT: AtomicU8`), weil
Upload-Worker aus Hintergrund-Threads loggen und der Tray auf dem Main-Thread gebaut wird. Sie
wird einmal beim Start gesetzt und erneut, wenn der Nutzer sie in den Einstellungen wechselt
(`Config.language`).

## 2. API

| Funktion | Zweck |
|---|---|
| `tr(key: &'static str) -> &'static str` | Übersetzt einen deutschen Satz (ohne Platzhalter). |
| `tr_for(Lang, key)` | Wie `tr`, aber für eine explizit übergebene Sprache; wird in Tests für beide Sprachen benutzt, ohne das Prozess-Global zu ändern. |
| `tr1(key, a)` / `tr2(key, a, b)` / `tr3(key, a, b, c)` | Wie `tr`, ersetzt aber **1/2/3** `{}`-Platzhalter von links nach rechts. Nimmt `impl Display`. |
| `Lang` | Enum `De` / `En` (Referenzsprache `De`). |
| `Lang::from_code(&str)` | Persistenz-Code (`"de"`/`"en"`) → `Lang`; liefert `None` für Unbekanntes. Eine Gegenrichtung (`Lang::code()`) gibt es nicht mehr. |
| `set_lang(Lang)` / `lang()` | Prozess-globale Sprache setzen / lesen (thread-sicher, atomar). |
| `system_lang()` | Best-effort-Systemsprache: POSIX-Umgebungsvariablen, auf macOS zusätzlich `NSLocale`. |

**Historisch:** `tr_ctx_for` (Kontext-Tags gegen gleichlautende Keys) und `tr_n`
(Singular/Plural) existieren im aktuellen Code nicht mehr. Zahlwörter laufen über `tr1` mit
einem festen Key wie `"{} Datei(en) werden hochgeladen …"`.

**Wann welche Funktion:** `tr` ohne Platzhalter; `tr1`/`tr2`/`tr3`, sobald Zahlen/Pfade/Strings
eingesetzt werden (Anzahl der `{}` muss zur Arity passen).

```rust
// src/rune_settings.rs – ohne Platzhalter
text(i18n::tr("Einstellungen")).key("page-title");

// src/rune_backup_live/targets.rs – drei Platzhalter
text(tr3(
    "{} / {} Dateien · {}",
    target_done,
    target_total,
    if folder.dedup {
        tr("Duplikate vermeiden")
    } else {
        tr("Duplikatprüfung aus")
    },
));

// src/upload.rs – Zahlwort über einen festen Key
s.log(tr1("{} Datei(en) werden erneut versucht …", n));

// src/rune_backup_live/conflict.rs – ein Platzhalter
.label(tr1("Dateiname-Konflikt: {}", &file_name))
```

`system_lang()` liest zuerst der Reihe nach `LC_ALL`, `LC_MESSAGES`, `LANG`; `de*` → `Lang::De`,
alles andere (auch `C`/`POSIX`) → `Lang::En`. Ist **keine** dieser Variablen gesetzt, liest
macOS die echte OS-Sprache über `NSLocale::currentLocale().localeIdentifier()`
(`os_lang()`, `src/i18n.rs`); Windows/Linux haben keine solche OS-API, dort bleibt es bei der
Umgebung (also `Lang::En`). Dafür kommt **kein** zusätzliches Crate dazu: `NSLocale` stammt aus
dem bereits vorhandenen `objc2-foundation` (Feature `NSLocale`).

## 3. Regeln

- **Kein hartkodierter UI-Text außerhalb von `src/i18n.rs`.** Jeder sichtbare String läuft
  durch `tr`/`tr1`/`tr2`/`tr3`. Die Marktplatz-Ländernamen in `countries.rs` sind
  ebenfalls UI-Text: `COUNTRIES` hält nur noch den deutschen Namen-Key, das Label baut
  `country_label` über `tr` + literale Domain.
- **Deutsche Fassung zuerst.** Ist die deutsche Formulierung nicht final, wird der Key nicht
  eingetragen — lieber kein Eintrag (Fallback = Deutsch) als eine falsche Übersetzung.
- **Keys sind `&'static str`.** `tr(format!(...))` kompiliert nicht — der Key muss ein
  String-Literal sein. Dynamische Teile gehen in die `{}`-Platzhalter der `trN`-Funktionen.
- **Platzhalter:** `{}` bei `tr`/`tr1`/`tr2`/`tr3` (Zahl und Reihenfolge zählen, von links nach
  rechts).
  ```rust
  // src/countries.rs – deutsche Namen über tr, Domain bleibt literal
  .map(|&(_, domain, name)| format!("{} · amazon.{}", tr(name), domain))
  ```
- **Bewusst NICHT übersetzt:**
  - **Endonyme**: „Deutsch" / „English" in der Sprachwahl (`src/rune_settings/general.rs`)
    stehen in ihrer eigenen Sprache, weil man sie sonst in der aktuellen UI-Sprache nicht finden
    könnte.
  - **Brand**: „Prime Photos" (und „Amazon Photos") sind Eigennamen. Sie laufen der
    Einheitlichkeit halber durch `tr(...)`, die Tabelle bildet sie aber auf sich selbst ab.
  - **Symbole / Widget-IDs**: z. B. das Menü-Symbol `"⋯"` und stabile Control-Keys
    (`settings-language`, `cfg`, `login-country`) — IDs sind intern und dürfen sich
    beim Sprachwechsel nicht ändern (sonst verliert die UI den Widget-Zustand).
  - **Diagnose-Strings**: Log- und Fehlerausgaben für Entwickler (z. B.
    `log::error!("tray: Menü konnte nicht aufgebaut werden: {e}")`) bleiben Deutsch; sie sind
    nicht für den Endnutzer.

## 4. Rezepte

### (a) Neuen String hinzufügen

1. Aufrufstelle auf `tr(...)` (bzw. `trN(...)`) umstellen, **Key = deutscher Satz**:
   ```rust
   ui.label(tr("Neuer Text"));
   ui.label(tr1("Datei: {}", &path));
   ```
2. Eintrag in der Tabelle `EN` (`src/i18n.rs`) ergänzen — in der passenden Feature-Gruppe
   (`// -- common`, `// -- settings`, `// -- login`, …), innerhalb der Gruppe alphabetisch
   (Umlaute nach ihrem Grundbuchstaben):
   ```rust
   ("Neuer Text", "New text"),
   ("Datei: {}", "File: {}"),
   ```
   Die Zahl der `{}` in der Übersetzung muss der Aufrufstelle entsprechen.
3. Fehlt der Eintrag (noch), greift der Fallback auf Deutsch — ein vergessener Eintrag bricht
   also nichts, sollte aber vor dem Commit nachgetragen werden.

### (b) Neue Sprache hinzufügen

Additiv, kein Umbau. Beispiel Spanisch:

1. `enum Lang { De, En, Es }` erweitern und `from_code()` um `"es"` ergänzen.
2. **Achtung:** die Abbildung auf `CURRENT` ist als `0 = De`, `1 = En` fest kodiert in
   `set_lang`/`lang`. Für eine weitere Sprache muss dieses Mapping (z. B. ein `u8`-Code pro
   `Lang`) mitgezogen werden.
3. Neue Tabelle `ES: &[(&str, &str)]` anlegen und in `tr_for` den `match`-Arm für die neue Sprache
   ergänzen.
4. Eintrag in der Sprachwahl in `src/rune_settings/general.rs` ergänzen (Endonym, z. B.
   „Español").
5. Zahlwörter laufen heute über `tr1` mit einem festen Key („1 Datei / N Dateien" ist als
   `"{} Datei(en) …"` formuliert); Sprachen mit komplexeren Pluralregeln bräuchten dafür eine
   eigene Erweiterung.

### (c) Sprachwahl & `Config.language`

`Config.language: Option<String>` (`src/config.rs`) — `None` bedeutet **Automatisch (System)**.
`#[serde(default)]`, damit eine alte `config.toml` ohne den Schlüssel weiter lädt; `None` wird
beim Speichern weggelassen.

Auflösung an beiden Stellen identisch:

```rust
// src/rune_backup_live/startup.rs – Produktionsroute, beim Start
let language = config
    .language
    .as_deref()
    .and_then(Lang::from_code)
    .unwrap_or_else(i18n::system_lang);
i18n::set_lang(language);
```

Dieselbe Auflösung steht in `src/rune_production_login.rs` (Login-Route) und in
`src/rune_settings.rs::set_initial_language` (Einstellungs-Fixture; ohne gespeicherte Sprache
folgt sie der System-Locale).

Die Sprachwahl in der laufenden App wirkt **sofort** (nicht erst beim Speichern): bei Änderung
setzt `LiveState::set_language` (`src/rune_backup_live.rs`) den `Config`-Wert, ruft
`i18n::set_lang` und wendet danach die Effekte aus `language_change::apply_effects` an:

```rust
// src/rune_backup_live.rs – nach einer Änderung der Sprache
crate::i18n::set_lang(lang);
language_change::apply_effects(|effect| match effect {
    language_change::Effect::RefreshMenu => crate::app_menu::refresh_labels(),
    language_change::Effect::RefreshTray => self.tray_route.request_label_refresh(),
    language_change::Effect::Persist => self.persist_settings(),
});
```

**Native macOS-Menüs (Prime-Photos-Vertrag, Issue #8 umgesetzt):** Rune installiert seine
Standardmenüs selbst mit festen englischen Titeln; `app_menu::rune_standard` passt daran die
vorhandenen Einträge von App-, Edit- und Window-Menü über ihre AppKit-Selektoren in place an
(englischer Rune-Titel → lokalisierter Titel, siehe `localized`) und benennt den About-Eintrag
über `rune_about` um. Beim Start läuft das in `install_rune_about` und danach in jedem Poll über
`ensure_rune_about_installed`; ein Sprachwechsel ruft `refresh_labels` auf. Das ist ein
Prime-Photos-Vertrag für **unser** macOS-Menü, keine Aussage über die Original-App; für
Windows/Linux ist `refresh_labels` ein No-op. Eine separate `menu_labels`-Quelle wie in der
früheren eframe-Oberfläche gibt es nicht mehr. Das Tray wird über den bestehenden
`tray_route::request_label_refresh`/`Tray::set_labels`-Pfad aktualisiert:

```rust
// src/tray.rs
pub fn set_labels(&self, paused: bool) {
    self.show_item.set_text(tr("Fenster anzeigen"));
    self.set_paused(paused); // "Alle anhalten"/"Alle fortsetzen"
    self.about_item.set_text(tr("Über Prime Photos"));
    self.quit_item.set_text(tr("Beenden"));
    let _ = self._tray.set_tooltip(Some(tray_tooltip(self.state)));
}
```

Der Tooltip (`tray_tooltip`) ist **zustandsabhängig**: „Prime Photos" (Idle, nur Brand), „Prime Photos – Angehalten", „Prime Photos – In Bearbeitung", „Prime Photos – Mit Fehlern abgeschlossen" bzw. „Prime Photos – Abgeschlossen".

## 5. Scope-Grenzen

- **Nur lateinische Sprachen** (mittel­fristig de, en, fr, it, es, pt). Jede weitere Sprache ist
  additiv (siehe Rezept b).
- **Kein CJK:** der gebündelte UI-Font ist Latin-only; Chinesisch/Japanisch/Koreanisch bräuchten
  einen gebündelten Noto-CJK-Font (~16 MB) oder einen pro OS geladenen Font.
- **Kein RTL:** Arabisch/Hebräisch wären nur in der Webview möglich,
  nicht im eigenen Chrome.
- **Die Amazon-Loginseite bleibt im Marktplatz-Default.** Amazon entscheidet die Seitensprache
  aus TLD + Cookies/`Accept-Language`. Wir erzwingen **nichts** (`lc-`-Cookie/`language`-Parameter
  wären unbelegt und könnten die Login-Seite verändern). Folge: deutsches UI + `amazon.com` ⇒
  englische Loginseite — bewusst akzeptiert.

## 6. Ablauf-Regeln (User-Entscheidung 2026-10-13)

- **Kein hartkodierter UI-Text außerhalb von `src/i18n.rs`.** Jeder sichtbare String läuft
  durch `tr`/`tr1`/`tr2`/`tr3`. Neue Strings kommen direkt zweisprachig dazu.
- **Deutsch + Englisch vollständig** (Stand 2026-10-13); jede weitere Sprache ist danach
  **additiv** (kein Umbau). Umfang mittelfristig: lateinische Sprachen (de, en, fr, it, es, pt).
- **Sprachwahl:** Default = OS-Locale, **Override in den Einstellungen**; im `Config`
  persistiert (`language`; serde-Default `None` = „Automatisch", damit alte `config.toml` weiter
  lädt — die OS-Locale greift erst zur Laufzeit über `system_lang()`).
- **Webview-Sprache:** Marktplatz-Default belassen — Amazon entscheidet die Seitensprache aus
  TLD + Cookies/`Accept-Language`. Wir erzwingen **nichts**.
- **Marktplatz-Ländernamen** in `countries.rs` sind ebenfalls UI-Text: `COUNTRIES` hält nur
  noch den deutschen Namen-Key, das Label baut `country_label` über `tr` + literale Domain.

## 7. Nicht verifiziert

- **`system_lang()` bei GUI-Start (macOS):** in einem Prozess **ohne** `LANG`/`LC_ALL`/`LC_MESSAGES`
  liefert `NSLocale::currentLocale().localeIdentifier()` ⇒ `"de_AT"` und `system_lang()` ⇒
  `Lang::De` (Referenzrechner, `defaults read -g AppleLocale` = `de_AT`) — der NSLocale-Fallback
  greift also, „Automatisch" wird auf macOS Deutsch statt Englisch. Offen bleibt das **echte**
  Doppelklick-/Finder-Startverhalten des Bundles (ob die Variablen dort tatsächlich fehlen) sowie
  Randfälle wie eine **Per-App-Sprachwahl** (macOS-Einstellung „Sprache für App"), die eine
  abweichende Locale liefern würde.
- **Tray-Refresh auf Windows/Linux:** `set_labels` ist nur auf macOS geprüft; das Verhalten der
  `tray-icon`-Labels nach `set_text` auf den anderen OS ist nicht verifiziert (auf diesem Rechner
  ist nur der macOS-Build lauffähig).
- **Nicht-lateinische Fonts / RTL:** nicht implementiert, daher auch nicht getestet.
- **Pluralformen:** es gibt keinen `tr_n` mehr; Zahlwörter laufen über `tr1` mit einem festen
  „Datei(en)"-Key. Korrekte Pluralregeln anderer Sprachen sind damit nicht umgesetzt.
